Getting Started

Install ClawGuard and run your first security scan in under 5 minutes.

Installation

ClawGuard is distributed as an npm package. Install it globally to use the clawguard command anywhere:

$ npm install -g @dribgib/clawguard

Verify the installation:

$ clawguard version
ClawGuard v1.0.1
Requirements

ClawGuard requires Node.js 18 or later. Docker is optional but needed for sandbox analysis.

Upgrading

To upgrade ClawGuard to the latest version:

$ npm update -g @dribgib/clawguard

Check which version you're running:

$ clawguard version

After upgrading, update your detection patterns to get the latest rules:

$ clawguard update-patterns
Breaking Changes

We follow semver. Major version bumps (v1 → v2) may include breaking changes to CLI flags or output format. Check the CHANGELOG before upgrading across major versions.

Your First Scan

Point ClawGuard at any skill directory. A skill is typically a folder containing a SKILL.md file and optional scripts, configuration, or dependency files.

$ clawguard scan ./my-skill

ClawGuard will automatically run static analysis, dependency scanning, and prompt injection detection. The output looks like this:

For a deeper scan that includes LLM-powered semantic analysis:

$ clawguard scan ./my-skill # includes semantic if configured
$ clawguard scan ./my-skill --fast # skip semantic, static only
$ clawguard scan ./my-skill --sandbox # include Docker sandbox

Understanding Results

Every scan produces a set of findings. Each finding has:

Field Description
ID Pattern identifier (e.g., T-CODE-001, T-DEPS-002)
Category Finding type: code, supply, prompt, semantic, chain, honeypot
Severity One of: critical, high, medium, low, info
Title Brief description of the issue
Location File and line number where the issue was found
Evidence The code snippet or text that triggered the finding
Remediation Suggested fix or action to take

Findings are aggregated into a risk score (0–100) using severity-based weights, which maps to a risk level.

Risk Levels

Each finding's severity is weighted to compute the total risk score:

Severity Weight Example
Critical 25 points Curl piped to bash, honeypot credential theft
High 10 points eval() usage, obfuscated variables, typosquat packages
Medium 4 points Dynamic imports, credential env reads, child_process usage
Low 1 point Deprecated packages, continuation patterns
Info 0 points Large files skipped, no scannable files found

The total score (capped at 100) maps to a risk level:

Risk Level Score Range Meaning
SAFE 0 – 10 No significant issues found. Safe to install.
LOW 11 – 25 Minor findings. Review but likely safe.
MEDIUM 26 – 50 Notable findings. Review carefully before installing.
HIGH 51 – 75 Serious issues detected. Do not install without review.
CRITICAL 76 – 100 Likely malicious. Do not install.

Configuration

Static analysis works immediately with no configuration. To enable LLM-powered semantic analysis, you need to configure an AI provider:

$ clawguard config

The interactive wizard will ask you to:

  1. Choose a provider: Anthropic (Claude), OpenAI (GPT-4), or Ollama (local)
  2. Enter your API key (stored securely with 0600 permissions)
  3. Select a model (or accept the default)

Configuration is saved to ~/.config/clawguard/config.json.

$ clawguard config --show  # view current config
$ clawguard config --test  # verify API connection
$ clawguard config --clear # reset configuration

Provider Selection

Anthropic (Claude)

Default models: Claude Sonnet 4, Claude Opus 4

Best for deep understanding and nuanced threat detection. Recommended for most users.

OpenAI (GPT-4)

Default models: GPT-4o, GPT-4o Mini

Fast analysis with good accuracy. Works well for high-throughput scanning.

Ollama (Local)

Default models: Llama 3 70B, Mixtral, DeepSeek

Complete privacy with no API costs. Requires Ollama running locally.

Environment Variables

Instead of storing API keys in the config file, you can use environment variables. This is recommended for CI/CD and shared environments:

# For Anthropic
$ export CLAWGUARD_API_KEY=sk-ant-...

# Or use provider-specific variables
$ export ANTHROPIC_API_KEY=sk-ant-...
$ export OPENAI_API_KEY=sk-...

Priority order: CLAWGUARD_API_KEY > config file API key > ANTHROPIC_API_KEY / OPENAI_API_KEY.

Security Tip

Avoid passing API keys via the --api-key command-line flag in production. Command-line arguments are visible in process listings (ps) and shell history. Use environment variables or the config file instead.
