GitHub Action

Automate ClawGuard security scanning in your CI/CD pipeline. Block dangerous skills before they reach production.

Quick Start

Add ClawGuard to any GitHub Actions workflow in one step:

yaml- name: Security Scan
  uses: mikecavallo/clawguard@v1
  with:
    path: '.'

This scans the repository root using static analysis and fails the workflow if HIGH or CRITICAL risk is detected.

Inputs

Input Required Default Description
path Yes . Path to the skill directory to scan
severity-threshold No high Minimum severity to fail the action: critical, high, medium, low
output-format No md Output format: md (human-readable) or json (machine-readable)
semantic No false Enable LLM-powered semantic analysis (requires api-key)
api-key No — API key for semantic analysis. Always use GitHub Secrets!
node-version No 20 Node.js version to use for running ClawGuard

Outputs

Output Type Description
risk-level string Risk level: SAFE, LOW, MEDIUM, HIGH, or CRITICAL
risk-score number Numeric risk score from 0 to 100
findings-count number Total number of security findings
report string Full JSON scan report (truncated to 50KB for GitHub output limits)

Basic Workflow

A minimal workflow that scans on every push and pull request:

yamlname: ClawGuard Security Scan
on: [push, pull_request]

jobs:
  security-scan:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: ClawGuard Scan
        uses: mikecavallo/clawguard@v1
        with:
          path: '.'
          severity-threshold: 'high'

This workflow will:

  1. Check out your code
  2. Install ClawGuard via npm
  3. Run static analysis, dependency scanning, and prompt injection detection
  4. Fail the workflow if risk level is HIGH or above

With Semantic Analysis

To enable LLM-powered semantic analysis, pass your API key via GitHub Secrets:

yaml- name: ClawGuard Full Scan
  uses: mikecavallo/clawguard@v1
  with:
    path: './skills'
    semantic: 'true'
    api-key: ${{ secrets.CLAWGUARD_API_KEY }}
Security: Use Secrets

Never hardcode API keys in workflow files. Always use ${{ secrets.YOUR_SECRET }} to reference keys stored in GitHub repository or organization secrets.

Using Outputs in Subsequent Steps

Access scan results in later steps using the step's output variables:

yamljobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: ClawGuard Scan
        id: scan
        uses: mikecavallo/clawguard@v1
        with:
          path: '.'
          severity-threshold: 'critical' # only fail on critical

      - name: Display Results
        if: always()
        run: |
          echo "Risk Level: ${{ steps.scan.outputs.risk-level }}"
          echo "Risk Score: ${{ steps.scan.outputs.risk-score }}"
          echo "Findings:   ${{ steps.scan.outputs.findings-count }}"

      - name: Block on High Risk
        if: steps.scan.outputs.risk-level == 'HIGH' || steps.scan.outputs.risk-level == 'CRITICAL'
        run: |
          echo "::warning::ClawGuard detected ${{ steps.scan.outputs.risk-level }} risk"
          echo "Review the scan report before merging."

PR Comment Integration

Post scan results as a comment on pull requests for easy review:

yamlname: ClawGuard PR Review
on:
  pull_request:
    types: [opened, synchronize]

permissions:
  pull-requests: write

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: ClawGuard Scan
        id: scan
        uses: mikecavallo/clawguard@v1
        with:
          path: '.'
          output-format: 'json'
          severity-threshold: 'critical'

      - name: Comment on PR
        if: always() && github.event_name == 'pull_request'
        uses: actions/github-script@v7
        with:
          script: |
            const riskLevel = '${{ steps.scan.outputs.risk-level }}';
            const riskScore = '${{ steps.scan.outputs.risk-score }}';
            const findings  = '${{ steps.scan.outputs.findings-count }}';

            const emoji = {
              SAFE: ':white_check_mark:',
              LOW: ':large_blue_circle:',
              MEDIUM: ':yellow_circle:',
              HIGH: ':orange_circle:',
              CRITICAL: ':red_circle:'
            };

            const body = [
              '## :shield: ClawGuard Security Scan',
              '',
              `| Metric | Value |`,
              `|--------|-------|`,
              `| Risk Level | ${emoji[riskLevel] || ':grey_question:'} **${riskLevel}** |`,
              `| Risk Score | ${riskScore}/100 |`,
              `| Findings | ${findings} |`,
              '',
              riskLevel === 'SAFE'
                ? ':white_check_mark: No security issues detected.'
                : `:warning: Review the [workflow run](${process.env.GITHUB_SERVER_URL}/${process.env.GITHUB_REPOSITORY}/actions/runs/${process.env.GITHUB_RUN_ID}) for details.`,
            ].join('\n');

            await github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body,
            });

Threshold Configuration

The severity-threshold input controls when the action fails:

Threshold Fails When Risk Is Use Case
critical CRITICAL only Loose: only block definitive malware
high (default) HIGH or CRITICAL Recommended for most projects
medium MEDIUM, HIGH, or CRITICAL Strict: flag anything notable
low LOW, MEDIUM, HIGH, or CRITICAL Very strict: flag any findings

The threshold comparison works by mapping risk levels to numeric values: SAFE=0, LOW=1, MEDIUM=2, HIGH=3, CRITICAL=4. The action fails when the detected risk level is greater than or equal to the threshold.

Full Example

A complete workflow with semantic analysis, PR comments, and conditional deployment blocking:

yamlname: Security Pipeline
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

permissions:
  pull-requests: write
  contents: read

jobs:
  clawguard:
    name: ClawGuard Security Scan
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Run ClawGuard
        id: scan
        uses: mikecavallo/clawguard@v1
        with:
          path: './skills'
          severity-threshold: 'high'
          output-format: 'json'
          semantic: 'true'
          api-key: ${{ secrets.CLAWGUARD_API_KEY }}
          node-version: '20'

      - name: Upload report artifact
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: clawguard-report
          path: 'clawguard-report.json'
          retention-days: 30

      - name: Summary
        if: always()
        run: |
          echo "### ClawGuard Results" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "- **Risk Level:** ${{ steps.scan.outputs.risk-level }}" >> $GITHUB_STEP_SUMMARY
          echo "- **Risk Score:** ${{ steps.scan.outputs.risk-score }}/100" >> $GITHUB_STEP_SUMMARY
          echo "- **Findings:** ${{ steps.scan.outputs.findings-count }}" >> $GITHUB_STEP_SUMMARY
