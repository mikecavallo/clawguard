Patterns

ClawGuard's detection engine is driven by YAML pattern files. This makes patterns easy to read, review, contribute, and update independently from the scanner itself.

Overview

ClawGuard uses three YAML pattern files, each targeting a different attack surface:

File Purpose Patterns
patterns/code.yaml Static code analysis patterns 60+ patterns for malicious code, obfuscation, credential theft, persistence, and more
patterns/deps.yaml Known-bad dependencies and popular packages for typosquat detection 100+ malicious npm packages, 40+ pip, 5+ Go, plus popular package lists
patterns/prompt.yaml Prompt injection detection patterns 30+ patterns for instruction overrides, persona manipulation, hidden content, and more

All pattern files are located in src/patterns/ in the source tree and dist/patterns/ in the installed package.

Pattern Structure

Code Pattern (code.yaml)

Each code pattern has the following fields:

- id: T-CODE-001
  name: curl-pipe-bash
  pattern: "curl.*\\|\\s*(?:bash|sh|zsh)"
  severity: critical
  description: "Curl output piped directly to shell - classic malware installation pattern"
  remediation: "Download scripts to a file first, inspect them, then execute if trusted"
Field Required Description
id Yes Unique identifier for the finding (e.g., T-CODE-001). Multiple patterns can share an ID if they detect the same class of threat.
name Yes Human-readable name for the specific pattern variant
pattern Yes Regular expression (JavaScript syntax). Applied with gi flags (global, case-insensitive). Must be double-quoted in YAML for proper escape handling.
severity Yes One of: critical, high, medium, low, info
description Yes What this pattern detects and why it matters
remediation No Suggested action to fix or address the finding
fileTypes No Array of file extensions to limit matching (e.g., [".js", ".ts"]). If omitted, pattern applies to all scannable files.

Prompt Pattern (prompt.yaml)

Prompt patterns can use either regex or programmatic checks:

# Regex-based pattern
- id: T-PROMPT-001a
  pattern: 'ignore\s+(?:all\s+)?(?:previous|above|prior)\s+(?:instructions?|prompts?|rules?)'
  severity: critical
  description: "Attempt to override system instructions"

# Programmatic check (function-based)
- id: T-PROMPT-003a
  check: containsInvisibleUnicode
  severity: high
  description: "Content contains invisible unicode characters that may hide instructions"

The check field references a built-in JavaScript function by name. Available checks:

  • containsInvisibleUnicode — detects 40+ invisible unicode character types
  • hasHiddenWhitespaceBlocks — finds suspicious whitespace that may conceal content
  • hasHomoglyphObfuscation — detects lookalike characters (Cyrillic, IPA, fullwidth)
  • hasRtlOverride — finds right-to-left override characters

Dependency Pattern (deps.yaml)

The dependency file has a different structure, organized by ecosystem:

# Known malicious packages
malicious_npm:
  - name: event-stream
    versions: ["3.3.6"]
    reason: "Supply chain attack - contained flatmap-stream malware"

  - name: crossenv
    versions: ["*"]
    reason: "Typosquat of cross-env, stole environment variables"

malicious_pip:
  - name: python3-dateutil
    versions: ["*"]
    reason: "Typosquat of python-dateutil, contained malware"

malicious_go:
  - name: github.com/gin-gonic/gin-contrib
    versions: ["*"]
    reason: "Typosquat of gin-contrib module"

# Popular packages (used for typosquat detection)
popular_npm:
  - express
  - react
  - lodash
  - axios
  # ... 50+ popular packages

popular_pip:
  - requests
  - numpy
  - pandas
  # ... 30+ popular packages
Field Description
name Exact package name
versions Array of affected versions. Use "*" for all versions.
reason Why this package is flagged (shown to users)

Dependency Patterns

The deps.yaml file contains two types of data:

Malicious Package Database

Known-bad packages across three ecosystems:

Ecosystem Count Notable Examples
npm 100+ event-stream@3.3.6 (supply chain), ua-parser-js@0.7.29 (compromised), crossenv (typosquat)
pip 40+ python3-dateutil (typosquat), jeIlyfish (homoglyph), colourama (typosquat)
Go 5+ github.com/gin-gonic/gin-contrib (typosquat module paths)

Popular Package Lists

Lists of legitimate, widely-used packages used by the typosquat detection engine. When a dependency name is within Levenshtein distance of 2 from a popular package, it triggers an alert. This catches attacks like:

  • lodas targeting lodash
  • axois targeting axios
  • requets targeting requests

Prompt Patterns

The prompt.yaml file contains 30+ patterns organized into 10 threat categories (T-PROMPT-001 through T-PROMPT-010). Each targets a specific prompt injection technique:

Category Patterns Technique
001: Direct Overrides 9 patterns "Ignore previous instructions", "new instructions:", "system prompt:", override commands
002: Persona Manipulation 11 patterns DAN jailbreak, "you are now free", mode switching, compromised AI roleplay
003: Hidden Instructions 5 checks Invisible unicode, whitespace blocks, homoglyphs, HTML comments, RTL override
004: Conditional Triggers 5 patterns Time delays, date conditions, user-presence triggers, environment checks
005: Tool Abuse 6 patterns Data exfiltration commands, credential access, dotfile references, webhook URLs
006: Deception 3 patterns "Don't tell the user", secrecy instructions, fake "true instructions"
007: Privilege Escalation 2 patterns Admin/root mode requests, debug mode activation
008: Prompt Leakage 4 patterns System prompt extraction, echo attacks, context dumping
009: Encoding Tricks 4 patterns Base64/hex decode setup, [INST] markers, ChatML tokens
010: Context Manipulation 3 patterns False prior agreement, memory manipulation, continuation injection

How Matching Works

Code Pattern Matching

  1. Patterns are loaded from code.yaml and compiled into JavaScript RegExp objects with gi flags
  2. Each file in the skill directory is read (up to 1MB per file)
  3. Every pattern is tested against the file content
  4. For each match, the line number and evidence snippet are recorded
  5. If a pattern specifies fileTypes, it only applies to files with matching extensions
  6. Findings are deduplicated by id + location + evidence
  7. Results are sorted by severity (critical first)

Prompt Pattern Matching

  1. Patterns are loaded from prompt.yaml
  2. The SKILL.md file is parsed into frontmatter (YAML) and body (Markdown)
  3. Regex patterns are tested against both frontmatter and body
  4. Programmatic checks (invisible unicode, homoglyphs, etc.) are run on the full text
  5. Semantic heuristics (capability mismatch, sentiment shift) are evaluated

Dependency Pattern Matching

  1. Dependency files (package.json, requirements.txt, go.mod) are parsed
  2. Each dependency is checked against the known-malicious database (exact name + version match)
  3. Each dependency name is checked for typosquatting via Levenshtein distance
  4. If network access is available, packages are verified against their registry

Contributing Patterns

ClawGuard's pattern files are open source. Contributing new patterns is one of the most impactful ways to improve the scanner.

Adding a Code Pattern

1

Choose an ID

Use an existing ID if the pattern fits a known category (e.g., T-CODE-001 for malicious commands). Create a new ID for genuinely new threat categories.

2

Write the Regex

Patterns use JavaScript regex syntax. They are applied with gi flags. Use double-quoted strings in YAML so backslashes are handled correctly:

pattern: "curl.*\\|\\s*(?:bash|sh|zsh)"
3

Set the Severity

  • critical — definitive malicious behavior, immediate danger
  • high — very likely malicious, needs review
  • medium — suspicious, could be legitimate
  • low — informational, minor concern
  • info — metadata, does not affect risk score
4

Test Against Fixtures

The tests/fixtures/ directory contains 10 test skills (both malicious and safe). Verify your pattern catches the intended behavior without false positives on safe skills.

$ npm run build && npm run test
5

Submit a Pull Request

Add your pattern to the appropriate YAML file and submit a PR to mikecavallo/clawguard. Include a description of the threat and any evidence (CVE, security advisory, real-world attack).

Pattern Quality Guidelines

Good patterns are specific (low false positive rate), documented (clear description and remediation), and tested (verified against real examples). Avoid patterns that trigger on common legitimate code.

Auto-Update

ClawGuard can fetch the latest patterns from the GitHub repository without updating the entire package:

$ clawguard update-patterns

This downloads the latest code.yaml, deps.yaml, and prompt.yaml from the main branch and replaces the local copies. It reports how many patterns were added or updated.

Stay Protected

New malicious packages and attack techniques are discovered regularly. Running clawguard update-patterns periodically ensures your scanner has the latest detections without waiting for a full npm release.
